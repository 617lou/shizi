# 快乐认字 · 小班识字游戏

给幼儿园小班（3-4 岁）用的识字游戏：**听发音 → 看图片 → 从几个大字里点出对的那个**。
总共 20 个常用字，分 4 关。单文件 HTML + 一小包语音文件，不需要联网、不需要后台、不需要安装。

## 有哪些文件

| 路径 | 说明 |
|---|---|
| `index.html` | 游戏本体（配置区 + 逻辑都在这一个文件里），播放 `audio/` 里的语音 |
| `audio/` | 生成好的语音：`zi/`=20 个单字、`ph/`=「对啦，这是X」、`ui/`=界面短语、`_voices/`=音色对比试听 |
| `识字游戏-单文件版.html` | **单个文件版**：语音已内联进去，适合单独传一部手机、在豆包/微信里打开 |
| `tools/gen-audio.py` | 生成语音（`python tools/gen-audio.py`） |
| `tools/build-standalone.mjs` | 生成单文件版（`node tools/build-standalone.mjs`） |
| `tools/smoke.mjs` | 自检（`node tools/smoke.mjs`）：字表、语音文件是否齐全、单文件版是否过期 |
| `tools/runtime-check.mjs` | 运行期校验（`node tools/runtime-check.mjs`）：无头 Chrome 真跑一关，查有没有音频被切尾、有没有回退系统 TTS；`--verbose` 附每个文件的时长明细 |
| `tools/tone-check.mjs` | 声调体检（`node tools/tone-check.mjs`）：量 20 个字的基频走势与末尾能量，改语速后用它对比 |
| `tools/listen.html` | 语音试听页：20 个字和所有短语逐个点着听 |

## 怎么玩

打开 `index.html`（或单文件版）即可。

- 点首页关卡卡片开始，先念关卡名，再出第一题。
- 一题：屏幕中间的图 + 语音念字 → 在下面 2 个（第三、四关是 3 个）大字里点。点图片 = 再听一遍，静置 4 秒 / 9 秒还会自动再念。
- 点对了：绿色高亮 + 撒星星 + 「对啦，这是……」，念完再进下一题。
- 点错了：卡片抖一下、**变灰不可再点**、念「再试一次吧」，不扣分不重来；同一题连错两次，正确答案开始闪，帮孩子收尾。
- 一关结束：给星星（零失误 3 星 / 失误 1-3 次 2 星 / 更多 1 星），再把这一关 5 个字连图带拼音念一遍。
- 星星进度存在浏览器本地（localStorage），换设备或清缓存会丢。

## 语音

**优先播放 `audio/` 里预先生成的语音**；文件缺失或播放失败时，自动回退到设备自带的系统 TTS（所以就算语音文件丢了，游戏也不会哑）。两种情况下都会：

- 静音时、或者既没有语音文件又没有可用的系统中文语音时，游戏页显示一行黄字「请家长念：人（rén）」——孩子不识字，没声音就没法玩。
- 首次必须点一下屏幕才会出声（浏览器硬性要求）。

语音是用微软 Edge 的神经网络中文语音（`edge-tts`）离线生成的，音色统一，在所有手机上听起来一样——这同时解决了安卓/苹果/微信 webview 系统语音音色乱七八糟的问题。

当前音色：**`zh-CN-YunxiaNeural`**（男声，官方标注 Cartoon / Cute）。最初用的是 `zh-CN-XiaoxiaoNeural`，换成 Yunxia 是因为孤立单字上的三声问题，详见下面「语速为什么按声调分开」。

**音色不满意**：先打开 `tools/listen.html` 点着听，底部有「手」「水」三个音色的对比（`audio/_voices/`）。选定后重新生成（**必须带 `--force` 重建全部语音**，否则会出现单字一个声音、反馈语另一个声音）：

```
python tools/gen-audio.py --voice zh-CN-XiaoyiNeural --force   # 或 Xiaoxiao / Yunxia
node tools/build-standalone.mjs                                # 单文件版也要重生成
node tools/smoke.mjs
```

### 语速为什么按声调分开

孤立合成时四个声调需要的时长不一样，用同一个语速发音质量差别很大。所以 `tools/gen-audio.py` 里按声调配了语速（`TONE_RATES`），声调由拼音上的声调符号自动识别（ā/á/ǎ/à 对应一/二/三/四声），不用手工维护名单：

| 声调 | 语速 | 本关的字 |
|---|---|---|
| 一声（高平） | `-15%` | 一 三 山 |
| 二声（中升） | `-15%` | 人 田 牛 羊 鱼 |
| 三声（降升） | `-15%` | 口 手 小 水 火 |
| 四声（全降） | `-25%` | 二 大 上 下 日 月 木 |

- **三声曾经放到 `-25%`**：三声是四声里最长的，孤立合成时引擎会把它挤进 250~340ms，"先降后升"的**升被压缩、音节末尾的能量提前衰减**，听感就是尾巴缺了一块（最初 Xiaoxiao 音色下 `手` 只有 340ms、升幅 8Hz）。换成 Yunxia 后三声本来就合得完整（升幅 +24~+58Hz），所以又调回 `-15%`，让它跟其他字一样利落。
- **四声反过来**：它是全降调、音节最短，放慢些才听得清"往下砸"的过程。

`node tools/tone-check.mjs` 会把 20 个字的声调形状打出来（基频 起/最低/末、降升幅度、末尾能量），改完语速用它前后对比。注意基频是启发式估计，短音节上会有跳动，**最终以耳朵为准**。

另外每个音频文件末尾自带约 0.6s 静音（引擎的句末停顿），所以文件长度看着比实际音节长很多，这是正常的。

> 授权提醒：`edge-tts` 走的是 Edge 朗读的接口，不是官方开放的 API。自己家孩子玩没问题，要是将来商用或公开发布，音频授权需要另行确认。

## 改字表 / 加关卡

改 `index.html` 顶部「配置区」：

```js
var CHARS = {
  '人': { id:'ren', pinyin:'rén', art:'🧒' },              // id=语音文件名（拼音，别重复）
  '上': { id:'shang', pinyin:'shàng', art:'🎈', stack:['🎈','🏠'] }  // stack 用两个图表示上下位置
};
var LEVELS = [
  { name:'第一关', chars:['一','二','三','人','口'], choices:2, color:'#ffd166' }
  // choices = 选项个数（2 或 3），color = 卡片主题色
];
```

加一个字的三步：① 在 `CHARS` 里加一行（`id` + 拼音 + 一个 emoji）；② 放进某个关卡的 `chars`；③ 重新生成语音：

```
python tools/gen-audio.py          # 只为新字补生成，已有的会跳过
node tools/build-standalone.mjs
node tools/smoke.mjs               # 自检
```

`tools/smoke.mjs` 会检查：脚本语法、字表里有没有缺 id/拼音/配图的字、id 有没有重复、关卡里的字是否都在字表里、**每个字的语音文件是否齐全**、单文件版是不是最新的、有没有外部依赖。删掉语音文件也能跑——它会告诉你缺哪几个。

## 发布到手机上

- **微信里打开**：必须用 https 链接，`file://` 在微信 webview 里不执行 JavaScript。走 GitHub Pages：仓库根目录放 `index.html`（`audio/` 一起推上去），Settings → Pages 选 `main` / `/ (root)`。注意 GitHub 免费账号的 Pages 只对 **public** 仓库开放。
- **豆包 app / 直接传文件**：用 `识字游戏-单文件版.html`，一个文件带走全部语音，不依赖同级目录。

## 已验证 / 未验证

用无头 Chrome（真机尺寸 360x640、390x844、844x390 横屏、820x1180）实际跑过：

- 首页 / 游戏页 / 过关页在四种视口下零溢出、零运行时报错；
- 跑完整关卡：题目播 `zi/`、答对播 `ph/right-`、过关播 `ui/done`，**TTS 调用为 0**（确实在用语音文件，没偷偷回退）；
- 54 个音频文件全部可解码（单字总长 1.5~1.8s、其中真正发音 0.19~0.79s；短语总长 2.4~2.6s、发音 ≤1.69s；界面总长 1.5~4.0s、发音 ≤3.1s），并且按每段的**实际发音结束点**核对了段落切换，**没有一段被下一句切掉**，切换余量最小 896ms；
- 缺语音文件时自动回退系统 TTS，流程照常推进、不报错；
- 单文件版内联语音可用（数据 URI 正常解码播放）。

没验证的：**发音本身对不对**（我听不了音频）。请打开 `tools/listen.html` 逐个点一遍，或直接在手机上玩一关——尤其确认「一」有没有被读成 yí/yì、「手/水/小/口」的三声是否完整。
